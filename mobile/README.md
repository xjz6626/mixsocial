# Mixsocial Android 客户端

当前移动端以 Android 为优先，Flutter 负责界面与系统 WebView，贴吧和知乎能力通过本地
`gomobile` AAR 调用 Go 核心。贴吧/知乎凭据进入系统安全存储，小红书会话由 WebView Cookie 存储管理，均不写入普通内容数据库。

主界面采用“首页 / 搜索 / 我的”导航：手机使用底部导航，平板和宽屏自动切换侧边栏，
并保留各标签页状态。首页保留平台和推荐/热榜/关注筛选，搜索页同时支持贴吧全站主题、
小红书公开笔记和知乎内容；列表接近底部时自动读取下一页并去重，宽屏瀑布流会扩展到三至四列。
主题可跟随系统或固定为浅色/深色；加载、空结果和错误恢复使用统一状态组件并提供读屏
语义。贴吧纯文字主题使用紧凑文字卡片，不显示无意义的空图片占位。

搜索页按“全部 / 小红书 / 贴吧 / 知乎”分别保存最近 20 条搜索历史，可点选重搜、逐条删除或清空当前
平台的记录。历史保存失败不阻止在线搜索，空白输入不会发送搜索请求。

“我的”中的浏览历史、本地收藏、稍后阅读支持按标题、摘要、作者和吧名搜索，多个关键词同时
匹配，并可按平台筛选。详情页的“更多操作”可加入稍后阅读、复制帖子链接或正文；稍后阅读
最多保存 300 条；满额时提示整理并拒绝新增，不会移除旧条目。本地收藏同样遵循这一规则。列表保存本身不下载正文。移出本地收藏或稍后阅读可以撤销，移出本地收藏
不会取消小红书平台收藏。短屏和横屏时，搜索筛选区随列表滚动，避免键盘遮挡操作。

贴吧阅读链路还包括：输入吧名直达、完整关注吧目录、最近访问、吧内搜索、按回复/发帖
时间排序、主题和楼中楼分页、倒序、只看楼主、楼层/楼主标记。本地阅读工具提供历史、
跨来源收藏、断网信息流回退、紧凑/标准/舒适密度、主题图与评论图全屏手势缩放，以及
按吧、关键词、视频和全部媒体过滤。贴吧点赞、评论和回复使用复用登录 Cookie 的百度
官方内嵌页面；作者与贴吧的关注/取消关注由本地 Go 适配器直接发送。作者和贴吧均可在本机屏蔽，屏蔽作者还会隐藏其评论与楼中楼；完整取舍见
[TiebaLite 功能对照](../TIEBALITE_PARITY.md)。

小红书使用真实的 Windows Chrome 桌面 UA 和 PC 宽视口，登录页支持扫码或验证码，
并拦截唤起 App 的非 HTTP 跳转。搜索支持 PC 端五组筛选；楼中楼首次打开即展开一页，
继续浏览时分页加载，暂时失败会保留已读回复并允许重试。
支持在楼中楼回复及点击评论图片全屏查看；点击作者可浏览主页简介和笔记/收藏/点赞分类。完整范围见
[小红书移动端功能对照](../XHS_PARITY.md)。

知乎复用与终端版相同的纯 Go 适配器，支持推荐、热榜、关注动态、搜索、问题/回答/文章/想法
详情、根评论分页、点赞、评论和回复。知乎没有可靠的默认收藏夹语义，因此 Android 端仍只使用
本地收藏，不把“关注问题”伪装成平台收藏。登录可在知乎官方 WebView 中完成，也可以遮罩导入
包含 `z_c0`、`_xsrf` 和 `d_c0` 的 Cookie；经 `/api/v4/me` 校验后才写入 Android Keystore。
匿名热榜通常可用，推荐、关注流和写操作需要登录，搜索及公开详情仍可能触发平台风控。

登录后可在“我的”打开“我的小红书主页”，查看自己的笔记、平台收藏和点赞，不再需要先找到
自己发过的笔记。平台收藏列表与本地收藏副本分开；主页切换分类或刷新时不会混入旧分页，
加载更多失败会暂停自动请求并提供重试。

头像兼容网页不同版本的头像字段、对象和备用地址，主页及本地缓存也保留备用地址。
小红书点赞、收藏、评论、回复、关注/取消关注以及评论点赞/取消赞复用登录网页发出的请求，检查与本次笔记、动作、用户和评论目标
匹配的服务端响应；网页乐观状态或已有的同文评论不能作为成功依据。请求结果不明时提示
刷新核对，不自动重复提交；目标错误、方向相反或混入其他笔记的请求会被阻止。平台收藏成功后才更新本地副本和收藏状态。
评论赞支持顶层和楼中楼，等待响应时防重复点击，失败不改状态。三站作者均可从信息流卡片的“关注与屏蔽作者”菜单或帖子详情管理原站关注：三站均在 App 内操作，小红书复用登录网页请求，贴吧和知乎经 Go 核心调用原站接口。贴吧吧内页支持直接关注与取消关注。作者操作先确认目标与当前状态，写入后回读状态；贴吧吧关注先解析吧编号，再用已关注吧目录确认结果。失败或状态不明时保留原状态，不自动重发；读取失败时可重试关注状态。官方作者页保留为主动选择的备用入口。作者屏蔽与原站关注互相独立，可从信息流卡片、详情菜单、作者主页或评论添加，并在“内容与阅读设置”解除；按平台和用户编号匹配，不按昵称匹配。屏蔽规则覆盖首页、搜索、作者/贴吧列表、本地收藏/历史、离线下载列表与评论，不删除已保存副本，并随所选偏好设置迁移。

小红书关注成功后同步已有作者
状态，不再强制刷新首页；本地记录失败只提示警告，不掩盖平台已确认的成功。

小红书图片保留 SSR 中的预览与高清地址：信息流按卡片实际像素尺寸解码缩略图，详情页先显示
低清预览再替换为最长边不超过 2560 的高清图，全屏查看会依次尝试去除已知 CDN 缩放规格的
原始地址、网页默认高清地址和预览地址，最长边上限为 4096。这样可兼顾高 DPI 屏幕清晰度、
失败回退和 Android 内存占用。

## 2026-10-26 阅读优化

- 小红书首页封面优先使用网页返回的原图/高清场景，兼容 `infoList` 和 `info_list`，保留备用地址。根据设备像素比和长图裁剪计算解码尺寸（最高 2560）；Android 对已适合显示的 JPEG/PNG/WebP/GIF 直接返回原始字节。CDN 未提供高清版本或高清请求失败时，仍可能显示预览图，不能凭空补出原图细节。
- 混合首页与搜索并行请求各来源，等本批请求完成后交错显示，手动刷新/追加加载最多等待 2 秒，首次或切换来源加载最多等待 4 秒；提前返回就立即显示，超时来源保留重试入口，迟到结果不插入当前列表，避免较快来源占满列表前部；刷新期间不追加分页。来源状态用紧凑单行文字显示，失败来源可单独重试；重复分页保留重试入口。连接诊断新增本机加载批次/各来源耗时记录（不含查询词、链接、凭据或内容）。
- 首页、来源、频道、查询词和小红书筛选组合保留最多 16 个内存阅读会话，并恢复本会话滚动位置；进程重启仍使用有限磁盘缓存，不承诺恢复网页游标。详情返回后的小红书列表会有界恢复已加载范围。
- 知乎问题展示独立回答及后续分页，可进入回答，再回到问题；回答/文章以原生组件按顺序显示正文、图片、链接、引用和代码。正文请求与首批评论分离，评论失败有单独重试。问题不展示不受支持的点赞操作。完整边界见 [ZHIHU_PARITY.md](../ZHIHU_PARITY.md)。
- 内容标识包含知乎类型；SQLite v3 迁移旧收藏、稍后阅读、标签、收藏夹和缓存引用。能由存量内容唯一确定类型的旧阅读位置/草稿自动迁移；有歧义的旧记录保留，不分配给任意一种内容。
- 本地收藏与小红书平台收藏显示不同状态。本地保存不增加平台收藏数；小红书详情还可单独“保存到本机”。平台操作成功但本地容量已满时，明确报告平台成功和本地副本失败。
- 登录、退出及导入登录状态会清理相关来源的信息流缓存、阅读会话和关注状态（含已确认的取消关注）；用户主动保存的本地内容保留。仅发现小红书 Cookie 时显示“已保存网页会话”，个人主页读取才验证具体账号。
- 贴吧聚合流每批最多读取 8 个吧，继续加载轮换所有吧，再推进页码；最多 5 条的短楼中楼可就地展开/收起，更多回复进入独立页面。阅读记录保存楼层、页码和上次回复数，“继续追楼”定位到当前已加载内容中更高的楼层。
- “内容与阅读设置”可选择来源混排权重（1～3）和按本机历史优先未读；应用于新返回的批次，不上传偏好，也不重新排列已经读到的屏幕。

### 显式离线下载

在详情菜单选择“下载离线正文与图片”，保存正文并可额外选最多 6 张图片。下载可取消，任一选定图片失败时保留之前的副本。副本总空间上限 200 MiB，满额要求用户整理；不自动下载评论或视频，不自动覆盖/删除旧副本。图片为最高 2560 边长的显示副本，并非文件原件备份。

在“内容与阅读设置 → 离线下载”或详情菜单“管理离线下载”中查看来源、时间、大小，直接离线阅读或删除副本。此阅读页面不会自动请求原站，也不加载未下载的网络图片。它与可自动淘汰的图片/首页缓存分开；设备迁移与普通收藏备份不包含这些下载文件。

### 设备迁移范围

生成迁移二维码前，可分别选择本地阅读资料、外观/内容偏好，以及每个平台的登录状态。账号默认不勾选；只有勾选的来源才读取和导出凭据。未选偏好不覆盖接收设备的设置。局域网加密传输、一次性二维码与超时机制继续生效。新版范围信息使用载荷 v2，可接收旧版 v1；新载荷需两端都使用新版。

### 浏览是否影响原站推荐

会存在向原站发送的请求，但不等于所有本机阅读行为都已同步：

| 行为 | 当前实现 |
| --- | --- |
| 在线获取首页、搜索、详情与图片 | 请求原站或其 CDN；使用有效登录会话的内容接口可能关联账号 |
| 小红书网页加载、网页滚动及网页互动 | 运行官方网页脚本，网站可能自行上报浏览/曝光等事件 |
| 平台点赞、收藏、发言、关注 | 成功后为真实平台行为；原站可能用于推荐 |
| Flutter 界面的每次滚动、停留时长 | 应用没有统一实现额外的跨三站浏览埋点；不保证每次操作被原站识别 |
| 本地收藏、稍后阅读、标签、字号、权重 | 留在本机，不自动转为平台互动或推荐偏好 |
| 打开显式下载的离线副本 | 不自动请求原站 |

小红书官方说明将浏览、点击、搜索、点赞、收藏等作为个性化推荐信号，见[个性化推荐说明](https://agree.xiaohongshu.com/h5/terms/ZXXY20250401002/-1)。这是平台机制说明，不证明本 App 的每个界面事件都被采集；是否持续推荐相似内容还由平台算法、账号设置和风控决定。本次没有新增用于训练原站推荐的额外埋点，也不伪造浏览行为。

## 环境

- Flutter 3.47 或更高版本（Dart 3.12+）
- Go 1.24.2 或更高版本
- JDK 17
- Android SDK Platform 37、Build Tools 36 和 NDK r28c
- `gomobile` 与 `gobind` 使用 `go.mod` 中固定的 `golang.org/x/mobile` 版本
- Node.js 18 或更高版本，用于在测试中执行 WebView 注入脚本及模拟网络响应

首次准备 Go 移动工具：

```bash
go install golang.org/x/mobile/cmd/gomobile@v0.0.0-20250911085028-6912353760cf
go install golang.org/x/mobile/cmd/gobind@v0.0.0-20250911085028-6912353760cf
```

不要额外执行 `gomobile init`；当前版本会尝试拉取不受 `go.mod` 固定的
`gobind@latest`，可能引入更高的 Go 版本要求。

## 构建与检查

先设置 `ANDROID_HOME`（或 `ANDROID_SDK_ROOT`）、`ANDROID_NDK_HOME` 与 Java 17，
然后在仓库根目录执行：

```bash
make mobile-aar
make mobile-check
cd mobile
flutter build apk --debug
flutter build apk --release
cd ..
make mobile-apk-check
```

AAR 输出到
`mobile/packages/mixsocial_core/android/libs/mobilecore.aar`，包含贴吧/知乎 Go 核心及 Android ARM64 与
x86_64，生成物不提交到 Git。APK 输出到 `mobile/build/app/outputs/flutter-apk/`。
未提供 `ANDROID_KEYSTORE_*` 环境变量时，release 构建会使用调试证书，只能作为本机
安装预览；正式发布仍必须使用下述 CI Secrets。品牌图标主图与生成说明保存在
[`assets/branding/`](assets/branding/)，Android 密度资源由主图生成。
`mobile-apk-check` 会复核 APK 签名、包名、版本信息，并确认 ARM64 与 x86_64 的 Go
运行库均已打包。

## GitHub Actions 发布

`.github/workflows/android-release.yml` 在推送 `v*` 标签时构建并发布 Android APK，
也可以从 Actions 页面手动选择已有标签，或更新 `.github/release-request.json` 后通过
标准 Git 推送启动已有标签。工作流会校验标签与 `pubspec.yaml` 版本、运行 Go/Flutter
检查、生成 AAR、验证 APK 签名，并同时上传 SHA-256 文件。

正式标签自动发布前，需要在仓库 Actions Secrets 中配置以下四项，凭据不会进入
源码、普通数据库或构建日志：

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

`v0.2.0` 可通过发布请求或手动运行工作流并允许调试签名来发布预览版。未配置上述
Secrets 时，后续由标签自动触发的构建会停止发布，避免不同的临时调试证书导致 APK
无法覆盖升级。

## 真机验证闸门

SQLite v3、媒体缓存与显式离线已实现；在正式发布本轮优化或扩展 iOS 适配前，仍需完成以下 Android 真机验证：

1. 小红书 PC WebView 扫码/验证码登录不唤起 App；贴吧和知乎 WebView/Cookie 登录后均杀进程并重启，确认登录状态仍有效。
2. 验证三个平台的推荐、热榜、关注和搜索，小红书搜索筛选和作者主页，以及关注吧目录、单吧列表/搜索/排序。
3. 验证倒序、只看楼主、本地收藏/历史/离线回退，以及按吧、关键词和视频过滤；验证稍后阅读重启保留、平台筛选/搜索、移除及撤销、搜索历史隔离与清空、复制链接/正文。
4. 验证小红书头像、评论/楼中楼首次展开、分页及失败重试，以及点赞/取消赞、收藏/取消收藏、关注/取消关注、评论和楼中楼回复；验证顶层/楼中楼评论点赞与取消赞、返回后的状态同步、我的主页和平台收藏；验证登录失效和网络中断时不会误报成功或自动重发；验证贴吧本地收藏和官方页面点赞/评论入口；验证贴吧作者、知乎作者与贴吧的 App 内关注/取消关注、刷新回读、跨页面同步、重复点击、切换账号和响应丢失后的状态核对。
5. 验证全部/小红书/贴吧/知乎切换后的布局选择与滚动位置恢复；验证知乎回答/文章/想法的点赞、评论、回复及评论分页。
6. 验证帖子主题图、顶层评论图和楼中楼图片均可全屏查看，放大后可完整平移，再观察数千关注吧目录和长列表滚动、前后台切换、WebView 销毁后的内存表现。

贴吧支持百度官方页面的可见 WebView 登录及安全导入 BDUSS。WebView 登录成功后，
应用读取百度域的 BDUSS/STOKEN，交给 Go 核心校验，并将有效凭据保存到系统安全存储。
知乎登录采用相同的可见页面与安全存储边界，只提取三个必要 Cookie；退出应用内登录不会清除
系统 WebView 的官方网页登录状态，避免误登出 WebView 中的其他站点账号。
